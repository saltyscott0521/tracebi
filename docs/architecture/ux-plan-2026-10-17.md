# UX plan — executing the 2026-10-17 audit

**Status: decided, in execution.** The audit is [[ux-audit-2026-10-17]]; this
is the work, cut into packages an agent can own. Read the audit first; it is
the *why*, this is the *what* and the acceptance test for each piece.

## Decisions (closed)

1. **Four places:** Reports (home) · Ask · Data · Review. The model switcher
   becomes a filter inside Reports and Data, not the frame of the app.
2. **The bar for the report output.** Type and restraint as Stripe's
   dashboard; density and chrome as Linear; the editorial register as a
   first-rate fund's quarterly letter. Operationally: one accent; no gradient,
   hatch, glow or resting shadow; hierarchy carried by type size and weight;
   every figure in tabular numerals; nothing truncated; every page framed by a
   masthead and a footer.
3. **Order:** Step 1 ships whole before Step 2 starts. Within a step,
   packages touching the same file run in sequence; disjoint packages may run
   in parallel.
4. **Invariants that no package may bend.** A presentation default never
   changes a number. The locked honesty lines (`tests/test_agent_guides.py`)
   survive verbatim. No new runtime dependency and no CSP change in the
   artifact. The receipt's own tones are never re-coloured by a theme. The
   discoverability definition of done applies to every authoring-surface
   change: vocabulary (`capabilities.py`), scaffold/showcase, both agent
   guides, in the same change.

## How work is done

- Branch `design-system-v2` off `main`. One commit per package, message
  naming the package (`DS-3: KPI as number + signal`). Merge to `main` at the
  end of each step when the full suite is green.
- Before a package's commit: `pytest tests/` (full), plus
  `TRACEBI_E2E=1 PYTHONPATH=$PWD pytest tests/test_ui_smoke.py` whenever the
  package touches the UI, `tracebi.js`, `tracebi.css` or any report package.
  Subprocess-spawning tests need `PYTHONPATH=$PWD`.
- Every visual package ends with captures: the changed surfaces at 1440 and
  390 wide, light and dark, looked at by the agent that made the change,
  before it reports done. "The tests pass" is not done for visual work.
- A package that finds the plan wrong says so in its report and stops at the
  boundary rather than improvising a different design.

## Step 1 — Report design system v2

Goal: a report with no `style.css` is the page we would show. Touches
`tracebi/reports/assets/tracebi.css`, `tracebi.js`, `_react_src/kit.jsx`
(then rebuild the vendored bundle per `REACT_NOTICE.md`), `template_package.py`
(the About block, mode default), the scaffolds, the showcase, the reference
reports, docs and guides.

### DS-1 Tokens, type scale, modes

- Section 1 of `tracebi.css` becomes the system: a seven-step type scale
  (`--tb-text-xs … --tb-text-3xl`, 12/13/14/16/20/28/40 at 1.25 ratio or
  close), weights 400/500/600, `--tb-tracking-tight` for ≥ 28px, tabular
  numerals on `.tb-kpi-value`, table cells, `[data-tb-figure="value"]`.
- One accent family: `--tb-chart-1` is derived from `--tb-accent` (same hue),
  not a second blue. The remaining seven series colours are re-checked for
  CVD separation against the new first.
- `auto` is the default mode: `template_package` emits `data-tb-mode="auto"`
  when `look.mode` is unset, for app and template pages alike. Dark values
  are reviewed as their own palette (surfaces, rules, chart series, muted
  ink), not inverted light.
- Themes (`tracebi/reports/themes/*.css`) collapse to accent presets on the
  one system: each file sets `--tb-accent`, `--tb-accent-text`, an optional
  display face, and nothing structural. `tracebi theme use` unchanged.
- Remove decoration from 12c: the hatched hero texture; the hero becomes
  `--tb-accent` (one colour per project, not `color-mix` per report).
- Acceptance: `tests/test_showcase.py`, the parity test, and the contrast
  checks in `scripts/ui_audit.py` pass; a grep for `linear-gradient`,
  `repeating-linear-gradient`, `box-shadow` in `tracebi.css` finds only the
  popover/menu/tooltip and the receipt drawer.

### DS-2 Frame: masthead, footer, the About block

- A masthead on every page. Template grammar: `.tb-masthead` with slots
  (`.tb-masthead-mark`, kicker, `h1`, standfirst, `.tb-masthead-meta` holding
  period, built time and the verdict chip). Kit: `<Masthead title kicker
  period mark>` renders it; `<Built>` moves inside it. The scaffolds and every
  reference report use it.
- The verdict chip in the artifact: `.tb-verdict` with the four states from
  DS-6, filled by `tracebi.js` from the manifest (Reproduces when the file's
  own fingerprints match at load — the runtime already knows; Not checked
  otherwise). Never green on a draft.
- A footer that ends the page: `.tb-footer` with sources (if the report
  names any) and "How these numbers were made" as one visible line and a
  `<details>`; the transform statement and the measure definitions move into
  the receipt drawer (DS-6). The 9px grey dump is gone from the page body.
- Page measure 1,200px, a 12-column `.tb-grid` with named spans
  (`.tb-span-4/6/8/12`), consistent vertical rhythm from `--tb-space-*`.
- Acceptance: no page shows the methodology text in the body; every
  reference report and scaffold carries a masthead; `about` text in
  `template_package.py` is covered by an updated test.

### DS-3 KPI as number + signal

- `.tb-kpi-value` lead at `--tb-text-3xl`, others at `2xl`; the lead is
  larger, not wider (drop `grid-column: span 2`).
- `<Kpi delta deltaFormat deltaGood="up|down">` and the template attribute
  `data-tb-delta` show a signed change with direction glyph and
  `--tb-good/--tb-bad`; `context` stays the one-line caption. Where the
  binding has no comparison, no delta: never invent one.
- Optional `spark` prop (already exists as `<Spark>`): aligned to the card
  baseline, 32px tall.
- Acceptance: app_lane records the delta's binding/cell as a claim; the
  scaffold and showcase use at least one delta; captures of the KPI strip at
  390px show four cards stacking cleanly.

### DS-4 Chart style (D3 engine in `tracebi.js`)

- Bars: band padding 0.45 (bars at 55% of the band), 2px radius on the free
  end, direct value labels (inside the bar when it fits, outside otherwise)
  using the figure's `valueFormat`.
- Category labels never truncate: wrap to two lines on `barh`, rotate on
  `bar` only past a density threshold, otherwise shrink the band.
- Axis ticks: thin to what fits (`ticks(width / 80)`), same formatter as the
  tables; gridlines at 6% ink; no axis lines; baseline only.
- Lines and areas: 1.5px stroke, end-point label, area at 10% of the series
  colour, no gradient.
- Tooltip: category, value, the measure's description from the manifest in
  plain words, and "Receipt →" that opens the drawer at that figure.
- Each of the six types has a reference rendering in the showcase.
- Acceptance: `portfolio_dashboard`'s *By fund* chart at 420px wide shows no
  colliding ticks; no label is cut with "…"; the selection/filter behaviour
  tests still pass.

### DS-5 Tables

- Numbers right-aligned with tabular numerals; a sticky header inside
  `.tb-scroll`; the data bar is a thin (6px) bar in its own cell after the
  number (`data-tb-bars` keeps its meaning), not a highlight behind the text;
  one totals row style (2px rule above, weight 600).
- Density follows `--tb-cell-pad` only.
- Acceptance: a capture of `portfolio_dashboard`'s holdings table and the
  editorial's sector table, light and dark.

### DS-6 The receipt as a certificate

- Drawer (section 13 + `tracebi.js`): header with the verdict chip, the
  report name, built time, model; then one row per figure: formatted value,
  label, the definition in words, the query in one line
  (`fair_value by dim_issuer.sector · order -fair_value`), fingerprint
  abbreviated to 8 characters with copy; the raw query JSON, the full
  fingerprint and git/rendered stamps behind a disclosure per figure and one
  at the end. Clicking a figure in the page opens the drawer scrolled to its
  row (already partly there).
- The same component serves the app's report page side panel (Step 2 reuses
  it; build it once, in the artifact first).
- Verdict chip states and colours, used everywhere from now on:
  Reproduces (green) · Needs a look (amber: source or model changed since the
  build, checks stale) · Does not reproduce (red) · Not checked (neutral).
- Acceptance: the receipt tests in `tests/` pass unchanged where they check
  content; the drawer at 390px is a full-height sheet; the honesty text
  ("does not claim the numbers are right") is present verbatim.

### DS-7 Editorial on the system

- `.tb-article` uses DS-1 tokens and the DS-2 masthead (hero register: the
  masthead on the accent ground, serif headline); the hatch is gone; the KPI
  strip is DS-3's; figures use DS-4; the methodology is in the receipt.
- `portfolio_book`'s and `cohort_brief`'s own `style.css` shrink to accent
  and face overrides only; both copies of `cohort_brief` identical.

### DS-8 Showcase, scaffolds, demo app, docs, guides

- `portfolio_showcase` rewritten to the system: no gradient, no shadows, the
  system's faces; still every figure kind and every interaction
  (`tests/test_showcase.py` is the contract, extend it for DS-2..6 markers).
- `_INIT_SAMPLE_APP_JSX`, `_app_scaffold.py` jobs, the `new-report`
  editorial template, the two `init --template` bundles and
  `tracebi/web/demo_app/reports/*` on the system (`aum_by_branch` may keep its
  faces and palette as the one bespoke example, on the new frame).
- `capabilities.py` names the new components and attributes; `AGENTS.md` and
  `_scaffold/init_agents.md` teach them; `docs/reference/app-jsx.md`,
  `template-html.md`, `docs/guides/styling-a-report.md` and
  `docs/architecture/design-direction.md` updated; `tests/test_agent_guides.py`
  extended for the new `data-tb-*` names.
- Fix: the served artifact at `/r/<name>` must not `fetch` the selection API
  from a `null` origin (either inline what it needs or detect the context).

### DS-9 Regression harness

- `scripts/ui_audit.py` also renders every report in both modes and both
  widths into `report-sheet.png`, and records per project: distinct font
  families, distinct accent hues, `box-shadow`/gradient occurrences. Baseline
  committed under `docs/architecture/`; a later run may not regress it.

Step 1 is done when: every reference report, demo report and scaffold renders
on one system in both modes; the receipt is the certificate; the audit's
"four visual languages" table collapses to one row (plus the one bespoke); and
the full suite plus the UI smoke are green on `main`.

## Step 2 — Reports as home, and the report page

### R-1 The library

- `/` → the library: folders by model (the existing `/api/folders` and
  `/api/reports` data), search, each row: display name, one-line description,
  verdict chip, built time, schedule if any. Model switcher becomes a filter
  chip row at the top. "At a glance" survives as a slim strip above the list.
  Notes-to-agent and the agent feed leave this page (to Build mode / dev).
- Sidebar: Reports · Ask · Data · Review, then Help. `PAGES` in `nav.js` is
  rewritten to these four; old addresses redirect.

### R-2 Names, not identifiers

- Every list and title uses `report.json` `name`; models get a `label`
  (`model_spec.py`, YAML and Python forms, optional, defaults to a
  title-cased identifier); identifiers appear in mono only in Code and the
  receipt's query line.

### R-3 One trust vocabulary in the app

- A `Verdict` component in `Shared.jsx` with DS-6's four states; used by the
  library row, the report header, History, Review and Build mode's figure
  badges (replacing "REPRODUCIBLE"). "Source changed since this build" is
  Needs a look everywhere at once (`/api/desk` already knows).

### R-4 The report page

- Full width, the artifact as delivered, the masthead's chip is the trust
  affordance; one command bar: Open in new tab · Share · Export · (analyst+)
  Rebuild · Edit as draft · (dev) Build; one side panel "About this build"
  with tabs Receipt (the DS-6 component) · Lineage · History · Files. Config
  is gone (its content is Files). Role-aware: buttons the role cannot use are
  not rendered (`/api/me`).

### R-5 History and phone

- History rows: what, verdict, when, how long, who; empty columns are not
  shown. Report list rows wrap descriptions to two lines on a phone; the
  receipt pill never overlaps content (anchor it to the masthead chip on
  narrow screens).

## Step 3 — Data and Review

### D-1 Data

- `/data/<model>`: the line as the page header (compact: three stations,
  the freeze points as labels, verdict summary), then tabs Model (diagram,
  tables, measures, relationships, storage, code) · Transform (flow, steps,
  runs, code, produces) · Sources · Runs. "Refresh data" lives on Transform
  only, as the primary action there. `/data` lists the models with one line
  each. Map folds in as the all-models view of the line (`/data` with the
  diagram toggled), one node style.

### D-2 Review

- `/review`: Needs attention first (failed runs, stale builds, publish
  requests awaiting the caller), then Drafts, then Verify a file as a quiet
  entry at the bottom. The Drafts empty state is written for a person, with
  the MCP tool names behind "for your agent".

### D-3 Retire

- Routes `/m/<model>/*`, `/models`, `/sources`, `/runs`, `/map`, `/drafts`,
  `/verify` redirect into the four places. `Overview.jsx`, `Map.jsx`,
  `TheLine.jsx` are reduced to what Data uses. `docs/guides/*` and the
  handbook's "How the app fits together" rewritten.

---

## Step 4 — Ask

- `/ask`: one input; the answer is a small table or chart from the model's
  existing query surface, with the measure definitions in words and the
  verdict chip; follow-ups refine; "Keep this" opens a draft (`/api/drafts`)
  with a one-figure app page. The query builder remains under "Advanced".
  Honesty: no number is shown that did not come from a stamped query.

---

## Reporting

At the end of each step the orchestrator records in `NOTES.md` what shipped,
what the captures showed, and what was deliberately left, and updates
`docs/architecture/ui-backlog.md`.
