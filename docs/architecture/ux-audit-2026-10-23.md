**Status: findings and a plan of eight packages, for execution.** Taken from

rebuilt with `run_workflow.py` (CRM unset, so the committed snapshot stood in),

The owner asked for consistency, readability, navigation, buttons, every
workflow, and above all **the explorer**: looking at the tables in a
connection, the warehouse and a model.

## Verdict

**The frame is right; the explorer is a catalogue, not an explorer.** Nav v3
holds: five places, the chain left to right, role tiers, a report page that
is the report. But at the point where a person wants to *look at data*, the
app shows names and counts and stops. Of the three places a table appears,
only a model's Tables tab shows any rows (the first 50, read by loading the
whole table into pandas), with no sort, search, filter, paging or address.
The warehouse shows a column profile and no rows. A connection shows column
names and no rows. A table has no page, so it cannot be linked, found in ⌘K,
or followed from the warehouse to the reports that use it. And on the demo
app the connection explorer lists the app's own state store (sessions, OAuth
tokens, run history) as if it were data: that is the one P0.

Around the explorer, the parts have drifted: four tab styles, two status
chips, seven date formats, three type vocabularies for one column. None is
large; together they are what makes the Data place read as several tools.

**Counts: 2 P0, 20 P1, 32 P2.**

## Decided by default

The three deviations awaiting a decision, with the recommendation each
package below assumes unless the owner says otherwise.

1. **FastAPI's Swagger at `/api-docs`, not `/docs`.** *Keep.* `/docs` is the
   product's manual for every role; Swagger is for integrators. Make it
   findable: link it from the API routes reference page and the startup
   banner, and list it in CHANGELOG under "moved" so an old bookmark has an
   answer. No redirect: `/docs` is taken by the place.
2. **Stage ⓪ "Sources" and the model's Sources tab.** *Keep the tab; make the
   station select it.* Stations 1 and 2 select this page's tabs; ⓪ should
   too, so the line reads the same left to right and the reader stays on the
   model. The tab already narrows to the model; it gains one link "Show every
   source" (as the Warehouse scope note has). The station stops navigating to
   `/data/sources?model=`.
3. **"Fed from" on every table a transform wrote.** *Say it once per
   transform.* The certificate records what the transform's run read, not
   what each table came from, so the per-table line overclaims. The
   Warehouse list groups tables by their writer, and the group header carries
   it: "holdings_transform · wrote 7 tables · read crm.issuer_ratings
   (snapshot inputs/issuer_ratings.csv) on that run". The table page says
   "The run that wrote this table read …", never "fed from".

## The plan

Eight packages, ordered by value. Each is one engineer in a worktree for a
few hours, with the usual gate: `pytest tests/`, `npm run build`, the audit
against the committed baseline (`--baseline docs/architecture/ui-audit-baseline-reference.json`,
and the demo baseline for U-1), captures at 1440/390 light/dark of what
changed, and the baseline recommitted when a count moves on purpose. U-2
lands before U-3, U-4 and U-5 (they read its API); the rest are independent.

### U-1 — Framework tables out of every explorer; demo data off the state store (P0)

**Scope.**
- `tracebi/sources.py`: one predicate, `is_framework_table(name)`: `tracebi_*`
  and `alembic_version`. `connection_tables`, `tracebi/workbench.py`
  `_warehouse_tables` / `warehouse_view`, and `GET /api/warehouse`
  (`tracebi/web/api/routers/sources.py`) drop them and return
  `hidden_framework_tables: <n>` beside `tables`. The model routes refuse a
  framework table by name (404, as for a missing one). U-2's table routes
  call the same predicate.
- The UI (`pages/Connectors.jsx`, `pages/Warehouses.jsx`,
  `components/Warehouse.jsx`, the model's Tables and Storage views) shows
  "N framework tables hidden" as one quiet line when `n > 0`.
- The demo: `PipelineRunner(db_url=…)` in `tracebi/web/demo_app/pipeline.py`
  and `wealth_pipeline.py` takes `tracebi.state.state_url()`; the demo's
  data stays on `TRACEBI_DEMO_DB_URL` / `data/demo.db`.

### U-2 — One read-only table API for every place a table lives

**Scope.** A table is addressed as `(source, table)`, where `source` is a
connector name or `inputs` (a file under `inputs/`, read with DuckDB's
`read_csv_auto` / `read_parquet`, the path confined to that folder). One
router, `tracebi/web/api/routers/tables.py`, reads through the locked,
read-only engine (`tracebi/model/engine.py` for DuckDB and files; for a SQL
connection, a statement built only from quoted identifiers and bound values,
with the project's statement timeout). Identifiers are checked against the
source's own catalog before use; nothing free-form reaches SQL.

- `GET /api/tables/{source}/{table}` →
  `{source, table, kind: "warehouse"|"connection"|"file", rows, rows_exact: bool,
  columns: [{name, type}], written_by, contract: {status, file, checks, note,
  checked_at}, read_by: [models], used_by: [{report, display_name}],
  transform_read: [{ref, snapshot?, fingerprint?}]}` — `type` is the
  engine's spelling (`BIGINT`, `DOUBLE`, `DATE`, `VARCHAR`), the one
  vocabulary (finding 13); `used_by` from each report's bindings over a model
  that reads the table.
- `GET /api/tables/{source}/{table}/rows?offset=0&limit=100&sort=<col>&desc=1&q=<text>&where=<json>`
  → `{columns: [{name, type}], rows: [[…]], offset, limit, total, total_exact,
  elapsed_ms}`. `limit` ≤ 500. `q` matches text columns (`ILIKE`); `where` is
  a closed list `[{column, op: "eq"|"ne"|"lt"|"le"|"gt"|"ge"|"contains"|"is_null"|"not_null", value}]`.
  Dates and timestamps go out as ISO strings, numbers as numbers.
- `GET /api/tables/{source}/{table}/profile` → `{columns: {name: {type, nulls,
  null_share, distinct, min, max, mean?, top: [{value, count}]}}}` for this
  one table, dates included (finding 18); the 50-column cap stays and says so.
- `GET /api/tables/{source}/{table}/export.csv` with the same `sort`, `q`,
  `where`: streamed by the engine (`COPY … TO STDOUT` equivalent), never
  through pandas.
- Not reachable: `200 {connected: false, reason, variable?}` on every route,
  the shape `/connectors/{n}/tables` already uses.
- Row counts (finding 16): exact for DuckDB and files; for a SQL connection
  the catalog estimate (`pg_class.reltuples`, Snowflake / BigQuery table
  metadata) with `rows_exact: false`, else `rows: null`; never a
  `count(*)` per listed table. `connection_tables` adopts the same rule, and
  `ROW_COUNT_CAP` goes.
- `GET /api/models/{name}/tables/{t}/preview` and `/export.csv` keep their
  shapes but resolve the model table to its `(connector, source table)` and
  read through these functions (finding 11).
- `MemoryConnector` lists its tables (finding 23).
- Role: viewer may read, as every other GET; folder permissions do not
  apply (tables are not reports). Framework tables refused (U-1).

**Files.** new `tracebi/web/api/routers/tables.py` (included in `main.py`),
`tracebi/sources.py`, `tracebi/workbench.py`,
`tracebi/web/api/routers/models.py`, `tracebi/connectors/memory_connector.py`;
CLAUDE.md's API Routes via the orchestrator.

**Acceptance.** A new step in `tests/e2e/test_reference_project.py`: for
`warehouse/fact_holdings`, `rows?sort=fair_value&desc=1&limit=5` returns the
five largest by fair value with `total: 25`; `q=Revolving` returns only
revolving-facility rows; `where=[{"column":"fund_id","op":"eq","value":2}]`
matches the count DuckDB gives; `export.csv` with the same filter has that
many lines + 1; `profile` gives `maturity` a min and max;
`inputs/holdings.csv` answers rows; `crm/issuer_ratings` answers
`connected: false, variable: "TRACEBI_CRM_URL"` with CRM unset (and real rows
on the Postgres the journey already provisions when one is available). A unit
test pins the closed `where` grammar: an unknown op, an unknown column and a
column name carrying a quote are each refused before any SQL runs.

**Closes** 11, 13 (API side), 16, 17, 18, 23.
