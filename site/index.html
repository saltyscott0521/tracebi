The problem

A model writes a number into a deck. By the time someone questions it, the query, the data, and the author are three tools away.

Legacy BI answered “who draws the chart.” The question now is “which numbers can anyone believe” — and a dashboard has no receipt, structurally. TraceBi draws the trust boundary where the numbers become a contract, and stamps everything downstream of it.

How it works

Three steps, from messy data to a report that proves itself.

Each phase hands the next a frozen artifact, so slow analysis and fast reporting never block each other — and the trust machinery attaches at the freeze points.

① Transform

Clean the data

Ordinary pandas — parse, dedupe, key — then sink clean star-schema tables into a warehouse you own.

transforms/ → warehouse.duckdb
② Model

Define the contract

A declarative star schema over the warehouse: grain, keys, measures — a few dozen lines a reviewer reads.

models/ → the semantic contract
③ Report

Publish the receipt

Every figure is a live query. Build one self-contained HTML file with the receipt embedded inside it.

reports/ → report.html + manifest

— freeze point · freeze point · every number stamped downstream —

The verifier

Hand someone the file. It re-checks itself.

The data, the query, and a SHA-256 fingerprint travel inside the HTML. A reviewer runs one command — no model, no warehouse, no account — and the file tells them whether a single byte moved.

What it claims

We won’t tell you a number is correct. We tell you it reproduces — and we let you check.

The receipt is a reproduction-and-integrity check, not a blessing. It proves the number on the page is the number the recorded query produced — not a transcription, not a hallucination. That honesty is the point: a claim you can check beats a claim you’re asked to trust. The whole framework is open-source and runs on your own machine; nothing phones home.
