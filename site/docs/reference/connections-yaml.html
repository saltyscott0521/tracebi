Connection files (YAML)

A file in connections/ declares a database or folder that holds data: its type and fields, with every secret kept out of the file as ${ENV_VAR}.

# connections/wh.yaml
name: wh                      # equals the file name
label: Sales warehouse        # optional: the name the app shows
type: postgres
url: ${TRACEBI_WH_URL}        # the value lives in .env or the environment

A model uses it by name:

# models/sales.yaml
connectors:
  - name: wh
    connection: wh

A SQL transform reads one of its tables with a header line -- source: wh.<table> (SQL transforms).

  • Add a connection on the Sources page (/data/sources) writes the file for a signed-in admin, with any secret in the encrypted store (Connect a database).
  • tracebi connect <name> --kind ... tests a database, writes the file and puts any secret in .env.
  • .yml works too. TRACEBI_CONNECTIONS_DIR moves the folder.
  • The project's own warehouse is not a connection file. It is the warehouse: block of tracebi.yaml (Project settings (tracebi.yaml)), and a model reads it with type: warehouse. That block resolves ${VAR} the same way, and its remote tier may name a duckdb connection file here.
  • The file loads with yaml.safe_load rules. A repeated key is an error, and an unknown key is refused with a suggestion.

Fields

Every file has name and type. All values are strings.

type Required Optional
duckdb database directory
csv directory encoding
sql, postgres, mysql url
snowflake account, user, password, warehouse, database schema (default PUBLIC), role
bigquery project, dataset credentials (path to a service-account file)
upload file (a .csv or .parquet file under inputs/)

sql takes any SQLAlchemy URL (sqlite:///inputs/bank.sqlite for a file in the project). postgres and mysql are sql with the database said in the type (postgresql+psycopg://…, mysql+pymysql://…). An upload connection is one file read as one table, named after the file: file: inputs/orders.csv is the table orders. The app's upload puts the file there (POST /api/inputs, at most 50 MB).

Field Meaning
label Optional name for people. The Sources page shows it large, with name small beside it and the kind of source in words ("Postgres", "SQLite file"). In Python: connector.label = "...". Never a credential and never resolved.

agents

Which of the connection's tables an agent may read through the gateway. Absent, none.

agents:
  tables: [accounts, clients]   # or "*" for every table, now and later

tracebi connect <name> --agents accounts,clients (or all) writes it, and so does ticking Agents may read on the connection's Tables list. tracebi connect --list prints each connection with its list. TraceBi's own tables (tracebi_*, alembic_version) are never readable, whatever it says. In code, tracebi.connections.agent_may_read(connection, table) is the one check; a loaded connector carries the list as agent_tables (["*"] for all, None for none).

${ENV_VAR}

Any value may be a reference, written as the whole value and named [A-Z_][A-Z0-9_]*. "x-${A}" is an error.

${NAME:-default} adds a default, used only when the name resolves nowhere:

url: ${TRACEBI_BANK_URL:-sqlite:///inputs/bank.sqlite}
Rule Detail
Secrets must be references password always. url may be literal only when it carries no credential (no password, no password=, token=, key= and the like in the query). sqlite:///data/x.db is fine.
Defaults are checked like literals A SQLite path passes, a URL with a password is refused, and password takes no default. The Sources page shows such a name as Set · default.
Literal paths stay in the project database and directory of a duckdb or csv connection, an upload's file, and the file of a sqlite:/// url: no absolute path, no ... Use a reference to point elsewhere. Relative paths resolve against the project root.
Resolved when used Reading the file reads no environment. The variable is read when the connection is used; an unset one fails there, naming the variable.
Lookup order The process environment, the project's .env, the project's encrypted store (tracebi secret set NAME, or Set… on the Sources page; Credentials), then the default. Nothing is copied into os.environ. tracebi secret list shows which names are missing.
Never shown /api/connectors and the Sources page show a reference as ${NAME} and a literal URL with its password hidden. A credential is never resolved to describe a connection.

Discovery and precedence

  • Files in connections/ are registered at startup and when they change, and forgotten when deleted, so the Sources page (/data/sources) lists them.
  • The app edits a file in place: the keys it changes are rewritten where they stand, and comments and order stay. It deletes a file only when no transform, pipeline step or model reads the connection, and otherwise says which do.
  • A model's connection: <x> reads connections/<x>.yaml first, then the older models/_connections/<x>.py that tracebi connect --python writes.
  • tracebi migrate connection models/_connections/<x>.py [--write] converts a module to YAML. It never deletes the module, and refuses a module that is not one of the types above or that builds a credential in code.
