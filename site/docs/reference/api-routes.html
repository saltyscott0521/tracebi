API routes

The HTTP API tracebi serve provides. Every route reads from the registry.

curl -s http://127.0.0.1:8000/api/health
# {"status": "ok", "version": "0.7.0"}
  • The role in each table is the minimum when roles are enforced (Environment variables).
  • To try routes in the browser, open /api-docs on a running server (FastAPI's Swagger UI; ReDoc at /api-redoc). /docs is the app's handbook.
  • A failed run returns {"message": "...", "exception_type": "ValueError", "traceback": ""} in detail. traceback is empty unless TRACEBI_DEV_MODE is set, because it would show file paths, the server's user name and package versions.

  • In /api/status, email_configured.detail lists the SMTP variable names and whether each is set, never a URL, host, user or password. schedules_in_server.detail is {"on", "count"}. auth.detail describes the sign-in setup. build_mode says the app runs in dev mode and gateway that it serves /mcp; Ask points at the agent when either is true.

Route Detail
/api/models, /api/models/{name} Each model carries label (Model files (YAML or JSON)) beside name, the identifier other routes take. Each fact lists runnable_measures: declared measures whose columns exist on its table. When the warehouse is not built yet, every declared measure is listed and a run reports the real error. TraceBi's own tables (tracebi_*, alembic_version) are left out and counted in hidden_framework_tables.
/query Takes a Queries spec; returns the result and a lineage graph. Computes but saves nothing, so a viewer may call it. Each row comes twice: data (raw values, used by CSV download) and display (text formatted as a built report would: the measure's declared format, else the shape default). NaN or infinity is null in data and an empty string in display.
/dimensions/{dim.attr}/values One attribute's distinct values, sorted, from the dimension's table: {"values", "total", "truncated"}. ?limit= default 200, at most 1,000. Unknown attribute: 404. A time grain or bin has no stored values: 422. Ask uses it for filters.
/preview, /export.csv Read through the table API below: the first rows (?rows=, default 50, at most 500) with an exact total and engine types (DOUBLE, DATE), or the CSV streamed. A source the table API does not read (a SELECT source, a CSV folder, Snowflake, BigQuery) uses the connector's own load. A framework table is 404.
/source The model's file, read-only (the Code tab). A model registered in Python has no file and says so.

Tables

One read-only API for every table, addressed as (source, table). source is a connector's name (a warehouse on any tier, a SQL connection, a MemoryConnector) or inputs, where table is a file's path inside inputs/ (CSV, TSV, Parquet or JSON, read by DuckDB, confined to that folder).

Method Path Role
GET /api/tables/{source}/{table} viewer
GET /api/tables/{source}/{table}/rows viewer
GET /api/tables/{source}/{table}/profile viewer
GET /api/tables/{source}/{table}/export.csv viewer
Route Returns
/{source}/{table} {source, table, kind: "warehouse" \| "connection" \| "file", rows, rows_exact, columns: [{name, type}], written_by: {transform, contract, at} \| null, contract: {status, file, checks, note, checked_at} \| null, columns_from: {column: {from, via?} \| {from: null, reason}} \| null, read_by: [model], used_by: [{report, display_name}], transform_read: [{ref, snapshot, fingerprint}]}. type is the engine's spelling. written_by, contract and transform_read (what the writing run read from outside the warehouse; snapshot when a committed file stood in) come from the certificate, for warehouse tables only; columns_from is a SQL transform's column lineage, as DuckDB's parser proved it (SQL transforms), null for a table pandas wrote. used_by lists reports the caller may view whose bindings read a model in read_by.
/rows ?offset=0&limit=100&sort=<col>&desc=1&q=<text>&where=<json> → {columns, rows, offset, limit, total, total_exact, elapsed_ms}. limit at most 500 (more is 422). q matches text columns, ignoring case. where is a JSON list of {column, op, value}, op one of eq ne lt le gt ge contains is_null not_null, the value of the column's kind. Dates come back as ISO strings. total is exact, except an unfiltered SQL connection with a catalog estimate (total_exact: false).
/profile {rows, columns: {name: {type, nulls, null_share, distinct, min, max, mean?, top: [{value, count}]}}}. min/max for numbers and dates, mean for numbers, top (the five commonest) for text and booleans. Past 50 columns nothing is profiled and note says so.
/export.csv The same sort, q and where, streamed from the engine.
  • Nothing free-form reaches SQL. The table must be in the source's catalog and every column must be the table's. A quoted identifier, unknown op or column, or a value of the wrong kind is 422 before any statement is built. Values are bound.
  • DuckDB reads use the read-only query connection. A SQL connection gets a short-lived engine for the request, stopped at engine.query_timeout_s (504 past it).
  • An unreachable source answers 200 {connected: false, reason, variable?}.
  • A framework table (tracebi_*, alembic_version) is 404.
  • Folder permissions do not apply: a table is not a report.

Route Detail
GET /api/reports Each report has name (the path routes take), display_name (report.json's name), form (spec, package or code), made_from (app.jsx, template.html or null), folder, owner (the last publisher, or a My published folder's owner), models (those its bindings read) and measures (the declared measure names they ask for, read from the file).
/run {name, html, manifest}: the real build, which verify --file can check.
POST /runs Starts the same build in the background and returns a run_id to poll.
/built The last build: output/<name>.html, else the path in the run store. A report never built on this server is built once on first open and kept. Fresh data comes from /run, /runs (Rebuild) or a schedule.
/cover The PNG of the last build's first screen, with an ETag of its write time (304 when unchanged). 404 when the build took none; it never builds.
/api/runs Run rows, newest first; kind, target, limit. Rows carry display_name beside target (a model publish carries its label; a pipeline run null). The HTML stays on disk; the row holds its path. A build row stores no verdict, so History shows the /api/desk re-check on a report's newest build and "Not checked" on older ones.
/api/runs/counts [{kind, target, runs, failed}] per target the caller may see.
/api/desk Only reports the caller may view: pins, drafts, verdicts, builds (each with values [{id, label, text, delta, spark}], its KPIs as built), sinks. Each verdict or build row has computed_at and cached. A verdict is kept while its manifest, its models and their warehouse (and certificate) are unchanged, in the process and in the state store (tracebi_verdicts), so a server just started reuses one computed before it; ?fresh=1 re-runs all. ?quick=1 re-runs none: a verdict not kept for its current inputs comes back pending with the last recorded verdict and its computed_at (or verdict: null), is not offered as open nor listed in verdicts, and the library shows it as Checking, never green, until it asks again without quick.
/download html: the last build. pdf: a print of it by headless Chromium, with no trace. xlsx: the Excel renderer, which derives no Number formats and runs the report to do so.
/lineage Transform → tables → model → queries → figures, from the last build's manifest. /mermaid returns a diagram.
/source The files that define the report (the spec, or report.json, template.html, style.css, script.js, report.py), read-only, and only files discovery registered.
/r/{name} A share link: the last build as a full page.

Folders can hide reports. With a _folder.yaml (Folder permissions (_folder.yaml)), a person without view on a report's folder finds it nowhere: not in /api/reports, /api/runs or /api/discovery, and every route above, including /r/{name}, answers 404 (an empty list for GET .../runs). A report they can see but may not act on is 403 with detail.required_permission.

One renderer. A registered report with no package is refused with 422 naming the fix (Reports).

Route Detail
POST /api/drafts {"kind", "path", "from_published"}. 201 with a new draft, 200 with the one the caller has. A Python model, or a report with a report.py, is 422 and says to edit it from a laptop. Starting a report draft needs build on its folder.
PUT .../files/{file} {"content"}; answers with the draft's new version.
/preview Renders the draft in memory against the published models plus the owner's draft models. Writes nothing.
/impact Model drafts only (a report draft is 422). Re-runs the recorded queries of every published report that reads the model, from each report's last build, against the draft: {reports: [{report, status, detail, moved, broken}], summary, needs_acceptance}. status is unchanged, moves (moved[].figures with id, old, new), breaks (broken[].error), not_built or not_checkable. Writes nothing.
/destinations Where a report draft may go, each mode: publish or request.
/publish {"note", "folder", "accept_impact"}; folder defaults to the draft's own path. Validates the draft, keeps the version it replaces under .tracebi/history/, copies it into the library and records a publish run. The draft is kept. With publish on the destination: 200, "status": "published". With only build: 202, "status": "requested" and the request. Less: 403. A checkable folder refuses a report that is not all re-runnable numbers (422). A model whose impact moves or breaks is 409 with the impact until "accept_impact": true; the accepted impact is stored in the run's detail. A model naming owners may be published only by an owner or an admin (403 otherwise, checked before the impact).
DELETE Removes the draft, never the published copy.
/api/folders The folders the caller may see, with their level and whether a publish there is direct or a request. personal is the caller's my-published/<sign-in name> (null with no sign-in identity). permissions (read-only, editable: false) only for manage and a personal folder's owner.
/api/publish-requests The caller's own requests and those into folders where they hold publish; each row carries can_decide. Approve answers 200 with the request, now approved. Reject needs {"note"}. Deciding a decided request is 422; one the caller may not see is 404.
/api/code-requests Python from tracebi push: {"files": {path: text}, "note"} (note required). An admin sees all; others their own. GET /{id} gives each file's diff, the runs an approval started, dry_run (a transform an agent proposed: its run against a throwaway copy; the list carries only {ok, summary}), and after approval commit_sha or commit_note (why it made no commit). Approve copies the files in, commits exactly them when the workspace is a git work tree with no uncommitted change to them (never pushed), and runs the pipelines they touch once; a request whose dry run failed is 422. Reject needs {"note"}.
/api/library/sync Exists only with TRACEBI_LIBRARY_SYNC_SECRET, sent as X-Hub-Signature-256 or X-TraceBi-Sync-Token (404 otherwise).

The MCP tools do the same: model_impact(path), publish_draft (with folder and accept_impact; status: requested with only Build there), list_publish_requests and decide_publish_request.

Read-only; framework tables are never listed.
GET /api/graph viewer The workspace as one graph, what Data's overview draws and the gateway's describe_project answers: {summary, nodes, edges, edge_facts}. Reports in a folder the caller cannot view are left out with their edges.
GET /api/graph/downstream?node=<id> viewer Every report figure that depends on one piece, table:<warehouse>.<table>, source_table:<connection>.<table> or measure:<model>:<measure>, grouped by report: {node, kind, measure, reads, summary: {figures, reports}, reports: [{id, name, label, open, built_at, trust, figures: [{id, kind, binding, label, text, open}]}], not_built}. Read from the last builds' manifests; starts nothing. 404 for any other node.

/api/graph is composed from the routes above, nothing new: each node is {id, kind, lane, parent, label, name, chip, sub, open, passport, gap}. id is kind:name (source:bank, file:inputs/holdings.csv, source_table:bank.accounts, transform:holdings_transform, group:holdings_transform, table:warehouse.fact_holdings, model:portfolio_model, report:portfolio_model/portfolio_book); lane is 0 sources, 1 transforms, 2 the warehouse, 3 models, 4 reports; parent puts a source table in its connection and a warehouse table in its writer's group; open is the app page that shows it. The passport says where it comes from (origin, never a credential: a connection set by a variable is named by the variable), who reads it (readers) and what wrote it (writers), when it last moved (moved: {at, how: written|built|changed|defined|snapshot|never}), what its checks or its last build's verdict say (trust: {state: ok|warn|bad|none, text}, in the app's words; a report's verdict is the one the desk last computed, never re-run here, else Not checked), and what an agent may read of it (agents: {state: ok|none, text}); a connection or file also carries reach: {connected, variable}. rows is present only when it is a number. gap: {reason} marks a node wired on one side only: a file no transform reads, a transform no pipeline runs and no certificate names, a warehouse table no model reads, a model no report reads. edges are [from, to] pairs from four facts only: a transform's file names the source (read_by), the sink certificate names the tables it wrote (to the writer's group), a model reads a group's tables, a report's bindings read the model. edge_facts are the edges DuckDB's parser proved, beside them: {from, to, kind: "lineage", columns}, a source table, input file or warehouse table to a warehouse table that a SQL transform computed columns of its columns from; such a table's passport carries columns_from, and a source table's readers list it. /api/graph/downstream is what the map's Depends on this panel reads (tracebi.graph.downstream, so the gateway can offer it too). A figure counts only when its last build's manifest says its binding read the piece: the query loaded the table (its fact or a joined dimension) or a warehouse view over it; for a source table, loaded it live or loaded a table that a transform reading it wrote; for a measure, asked for it or for a measure defined from it, and a value figure only when its own cell is one of those. A binding derived in Python records no loads and never counts. text is what the built page prints for the figure (the desk's values, its KPIs; null for a chart or a table), trust the report's verdict in the graph's words, open the report page at that figure (/reports/<name>?figure=<id>, which opens its trace). measure is the measure's definition. not_built names the reports that read the piece through their model but have no build here. Reports the caller cannot view are left out.

summary counts each kind in the flow (gaps apart, in gaps), stale tables, groups whose checks passed (checks: {satisfied, of}), and what agents may read (agents: {source_tables, models, reports}).

Add a route

  1. Add a file under tracebi/web/api/routers/.
  2. Include it in main.py.
  3. Read resources only from the registry. Never import app-specific objects.

Any write route the authorizer does not recognise requires analyst, so a new route is guarded by default. Add an explicit rule when it needs admin.
