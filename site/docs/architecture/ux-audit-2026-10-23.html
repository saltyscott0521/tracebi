UX and UI audit, pass 3 — 2026-10-23

Status: findings and a plan of eight packages, for execution. Taken from 7034845 (Navigation v3 merged): a fresh UI build, the reference project rebuilt with run_workflow.py (CRM unset, so the committed snapshot stood in), and the demo app (TRACEBI_APP=tracebi.web.demo_app) served beside it. Every place, tab and panel captured at 1440 and 390, light and dark, as admin; the viewer and analyst tiers through proxy-header auth; scripts/ui_audit.py against the committed baseline (score 58 → 72, 6 fixed, 1 new: the Never built chip's tap target on an open report). Zero console errors in any context. Earlier passes: UX and UI audit — 2026-10-17, UX and UI audit, pass 2 — 2026-10-18; open items in UI backlog; the bar in The UI quality bar; the frame in Navigation v3 — Docs as a place, Data as the chain.

The owner asked for consistency, readability, navigation, buttons, every workflow, and above all the explorer: looking at the tables in a connection, the warehouse and a model.

Verdict

The frame is right; the explorer is a catalogue, not an explorer. Nav v3 holds: five places, the chain left to right, role tiers, a report page that is the report. But at the point where a person wants to look at data, the app shows names and counts and stops. Of the three places a table appears, only a model's Tables tab shows any rows (the first 50, read by loading the whole table into pandas), with no sort, search, filter, paging or address. The warehouse shows a column profile and no rows. A connection shows column names and no rows. A table has no page, so it cannot be linked, found in ⌘K, or followed from the warehouse to the reports that use it. And on the demo app the connection explorer lists the app's own state store (sessions, OAuth tokens, run history) as if it were data: that is the one P0.

Around the explorer, the parts have drifted: four tab styles, two status chips, seven date formats, three type vocabularies for one column. None is large; together they are what makes the Data place read as several tools.

Counts: 2 P0, 20 P1, 32 P2.

Findings

Severity: P0 blocks a workflow or exposes what must not be shown, P1 hurts every day, P2 polish. File references are to web/ui/src/ unless they start with tracebi/ or examples/.

Decided by default

The three deviations awaiting a decision, with the recommendation each package below assumes unless the owner says otherwise.

  1. FastAPI's Swagger at /api-docs, not /docs. Keep. /docs is the product's manual for every role; Swagger is for integrators. Make it findable: link it from the API routes reference page and the startup banner, and list it in CHANGELOG under "moved" so an old bookmark has an answer. No redirect: /docs is taken by the place.
  2. Stage ⓪ "Sources" and the model's Sources tab. Keep the tab; make the station select it. Stations 1 and 2 select this page's tabs; ⓪ should too, so the line reads the same left to right and the reader stays on the model. The tab already narrows to the model; it gains one link "Show every source" (as the Warehouse scope note has). The station stops navigating to /data/sources?model=.
  3. "Fed from" on every table a transform wrote. Say it once per transform. The certificate records what the transform's run read, not what each table came from, so the per-table line overclaims. The Warehouse list groups tables by their writer, and the group header carries it: "holdings_transform · wrote 7 tables · read crm.issuer_ratings (snapshot inputs/issuer_ratings.csv) on that run". The table page says "The run that wrote this table read …", never "fed from".

U-2 — One read-only table API for every place a table lives

Scope. A table is addressed as (source, table), where source is a connector name or inputs (a file under inputs/, read with DuckDB's read_csv_auto / read_parquet, the path confined to that folder). One router, tracebi/web/api/routers/tables.py, reads through the locked, read-only engine (tracebi/model/engine.py for DuckDB and files; for a SQL connection, a statement built only from quoted identifiers and bound values, with the project's statement timeout). Identifiers are checked against the source's own catalog before use; nothing free-form reaches SQL.

  • GET /api/tables/{source}/{table} → {source, table, kind: "warehouse"|"connection"|"file", rows, rows_exact: bool, columns: [{name, type}], written_by, contract: {status, file, checks, note, checked_at}, read_by: [models], used_by: [{report, display_name}], transform_read: [{ref, snapshot?, fingerprint?}]} — type is the engine's spelling (BIGINT, DOUBLE, DATE, VARCHAR), the one vocabulary (finding 13); used_by from each report's bindings over a model that reads the table.
